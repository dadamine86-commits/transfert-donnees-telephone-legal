Transfert Données Téléphone est une application de migration de données entre appareils Android. L’objectif de l’application est de permettre à l’utilisateur de transférer ses données accessibles depuis un ancien téléphone Android vers un nouveau téléphone Android, de manière locale et sécurisée.

1. Données traitées par l’application

Selon les modules utilisés par l’utilisateur, l’application peut traiter les catégories de données suivantes :

  • Contacts ;
  • Événements de calendrier ;
  • Photos et vidéos sélectionnées par l’utilisateur ;
  • Fichiers et documents sélectionnés par l’utilisateur ;
  • Fichiers audio ou musique sélectionnés par l’utilisateur ;
  • SMS, si le module SMS est activé et utilisé par l’utilisateur ;
  • Journal d’appels, si le module d’historique d’appels est activé et utilisé par l’utilisateur.

L’application ne transfère que les données accessibles par Android et autorisées par l’utilisateur. Certaines données peuvent ne pas être disponibles selon la version Android, le constructeur du téléphone, les permissions accordées ou les restrictions du système.

2. Transfert local uniquement

Les transferts sont effectués localement entre les appareils de l’utilisateur. L’application utilise un appairage par QR code, une connexion locale et un canal de transfert sécurisé.

Les données transférées ne sont pas envoyées vers un serveur de Neova Labs, SASU AMINE TELECOM ou un service cloud externe. L’application n’a pas pour objectif de sauvegarder les données personnelles sur Internet.

3. Chiffrement et sécurité du transfert

Les données transférées entre les deux appareils passent par un canal sécurisé. L’application utilise un mécanisme d’appairage et de chiffrement afin de protéger les données pendant leur transfert.

Les transferts importants peuvent être découpés en fragments afin d’améliorer la stabilité et la fiabilité. Des contrôles d’intégrité peuvent être utilisés pour vérifier que les données reçues correspondent aux données envoyées.

L’application est conçue pour éviter les fichiers temporaires en clair persistants pendant les transferts.

4. Contacts

Si l’utilisateur choisit de transférer ses contacts, l’application peut demander les permissions de lecture et d’écriture des contacts.

  • Sur l’ancien appareil, les contacts sont lus uniquement pour préparer le transfert.
  • Sur le nouvel appareil, les contacts sont importés si l’utilisateur accorde la permission nécessaire.
  • Les contacts ne sont pas envoyés à un serveur externe.

5. Calendrier

Si l’utilisateur choisit de transférer ses événements de calendrier, l’application peut demander les permissions de lecture et d’écriture du calendrier.

  • Sur l’ancien appareil, les événements compatibles sont lus pour préparer le transfert.
  • Sur le nouvel appareil, les événements sont importés dans un calendrier accessible si Android l’autorise.
  • Les événements de calendrier ne sont pas envoyés à un serveur externe.

6. Photos, vidéos, documents et audio

Pour les photos, vidéos, documents et fichiers audio, l’application privilégie une sélection explicite par l’utilisateur. Cela signifie que l’utilisateur choisit lui-même les fichiers à transférer.

L’application ne réalise pas de scan complet du stockage sans action claire de l’utilisateur. Les fichiers sélectionnés sont transférés localement vers le nouveau téléphone.

7. SMS

Si le module SMS est activé, l’application peut demander l’accès aux SMS uniquement pour permettre leur migration entre deux appareils appartenant à l’utilisateur.

  • Sur l’ancien appareil, l’application peut lire les SMS afin de les transférer.
  • Sur le nouvel appareil, Android peut exiger que l’application devienne temporairement l’application SMS par défaut afin de restaurer les SMS.
  • L’utilisateur est informé avant toute demande de permission ou changement d’application SMS par défaut.
  • Après le transfert, l’application guide l’utilisateur pour remettre son application SMS habituelle.
  • L’application n’utilise pas le contenu des SMS à des fins publicitaires.
  • Les SMS ne sont pas envoyés à un serveur externe.

Les MMS peuvent être plus complexes à transférer selon les versions Android, les opérateurs et les appareils. Si le transfert MMS n’est pas pris en charge dans une version de l’application, cela sera indiqué clairement à l’utilisateur.

8. Journal d’appels

Si le module d’historique d’appels est activé, l’application peut demander l’accès au journal d’appels uniquement pour permettre sa migration.

  • Sur l’ancien appareil, l’application peut lire l’historique d’appels si l’utilisateur accorde la permission.
  • Selon la version de l’application et les restrictions Android, l’historique d’appels peut être affiché dans l’application au lieu d’être restauré dans l’application Téléphone native.
  • Si une restauration native du journal d’appels nécessite que l’application devienne temporairement l’application Téléphone par défaut, l’utilisateur sera informé clairement avant toute demande.
  • L’application ne passe aucun appel automatiquement.
  • L’application n’utilise pas l’historique d’appels à des fins publicitaires.
  • L’historique d’appels n’est pas envoyé à un serveur externe.

9. Publicités AdMob

L’application peut afficher des publicités via Google AdMob. Les publicités permettent de financer le développement et la maintenance de l’application.

L’application utilise le système de consentement Google UMP lorsque cela est nécessaire, notamment pour respecter les règles de consentement applicables dans l’Espace économique européen, au Royaume-Uni et en Suisse.

Les données transférées par l’utilisateur, comme les SMS, le journal d’appels, les contacts, le calendrier, les photos, les vidéos, les fichiers ou l’audio, ne sont pas transmises à AdMob par notre code et ne sont pas utilisées par nous pour cibler les publicités.

Des données publicitaires techniques peuvent être traitées par Google AdMob selon le consentement de l’utilisateur, par exemple l’identifiant publicitaire de l’appareil, des informations techniques de l’appareil ou des données nécessaires à l’affichage et à la mesure des annonces.

10. Aucun affichage publicitaire pendant les transferts sensibles

Par conception, l’application ne doit pas afficher de publicité pendant les étapes sensibles suivantes :

  • Scan ou génération du QR code ;
  • Appairage entre les appareils ;
  • Demandes de permissions ;
  • Changement temporaire d’application SMS ou Téléphone par défaut ;
  • Transfert de données en cours ;
  • Restauration des SMS ou de l’historique d’appels ;
  • Écrans expliquant les permissions sensibles.

Les publicités peuvent être affichées uniquement sur des écrans non sensibles, par exemple l’accueil, les réglages ou certains écrans de rapport après la fin complète d’un transfert.

11. Conservation des données

L’application n’a pas pour objectif de conserver durablement les données transférées. Les données sont traitées pour effectuer le transfert demandé par l’utilisateur.

Certaines données techniques temporaires peuvent être utilisées pendant la session de transfert afin d’assurer la stabilité, l’intégrité et le bon fonctionnement du transfert. Ces données temporaires ne sont pas destinées à être conservées après la fin du transfert.

Si l’application propose une section locale, par exemple pour afficher un historique d’appels transféré dans l’application, ces données restent stockées localement sur l’appareil de l’utilisateur et ne sont pas envoyées à un serveur externe.

12. Permissions Android

L’application demande uniquement les permissions nécessaires aux fonctionnalités utilisées. Les permissions peuvent varier selon la version de l’application, la version Android et les modules activés.

Les permissions peuvent inclure notamment :

  • Caméra : pour scanner un QR code d’appairage ;
  • Internet / réseau : pour établir une communication locale et utiliser les services publicitaires si activés ;
  • Contacts : pour lire ou importer les contacts ;
  • Calendrier : pour lire ou importer les événements compatibles ;
  • SMS : uniquement pour le transfert SMS si l’utilisateur active ce module ;
  • Journal d’appels : uniquement pour le transfert de l’historique d’appels si l’utilisateur active ce module.

13. Données non vendues

Neova Labs / SASU AMINE TELECOM ne vend pas les SMS, le journal d’appels, les contacts, les fichiers, les photos, les vidéos, l’audio ou les données de calendrier de l’utilisateur.

14. Responsabilité de l’utilisateur

L’utilisateur doit vérifier que les données transférées ont bien été importées sur le nouvel appareil. Certaines données peuvent ne pas être transférées si Android, le constructeur, les permissions ou le format des données ne l’autorisent pas.

L’utilisateur reste responsable de ses sauvegardes personnelles. Il est recommandé de conserver une sauvegarde indépendante avant toute migration importante.

15. Modifications de cette politique

Cette politique de confidentialité peut être mise à jour afin de refléter les évolutions de l’application, des fonctionnalités, des permissions ou des obligations légales.

La date de dernière mise à jour affichée en haut de cette page indique la dernière modification importante.
