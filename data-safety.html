Cette page résume la manière dont Transfert Données Téléphone traite les données pendant une migration. Elle complète la politique de confidentialité et les conditions d’utilisation.

1. Principe général

Transfert Données Téléphone est conçue pour transférer des données entre deux appareils Android appartenant à l’utilisateur. Le transfert est conçu pour fonctionner localement entre les appareils, sans serveur externe de Neova Labs ou de SASU AMINE TELECOM.

Les données transférées ne sont pas destinées à être collectées, revendues ou exploitées par Neova Labs / SASU AMINE TELECOM.

2. Données pouvant être traitées

Selon les modules utilisés et les permissions accordées, l’application peut traiter les catégories suivantes :

  • contacts ;
  • événements de calendrier ;
  • photos et vidéos sélectionnées ;
  • fichiers et documents sélectionnés ;
  • fichiers audio ou musique sélectionnés ;
  • SMS, si le module SMS est disponible et activé ;
  • historique d’appels, si le module correspondant est disponible et activé.

3. Données non envoyées à nos serveurs

Neova Labs / SASU AMINE TELECOM ne met pas en place de serveur destiné à recevoir ou stocker les données transférées par l’utilisateur.

Les contacts, SMS, historiques d’appels, calendriers, photos, vidéos, documents et fichiers audio transférés ne sont pas envoyés vers un serveur appartenant à Neova Labs ou SASU AMINE TELECOM.

4. Transfert local et chiffrement

L’application utilise un appairage entre les appareils, notamment par QR code, puis une communication locale entre les deux appareils.

Les données transférées passent par un canal sécurisé afin de réduire les risques d’interception pendant le transfert.

Les fichiers volumineux peuvent être transférés par fragments pour améliorer la stabilité. Des contrôles d’intégrité peuvent être utilisés afin de vérifier que les données reçues correspondent aux données envoyées.

5. Publicités et données transférées

L’application peut utiliser Google AdMob pour afficher des publicités sur certains écrans non sensibles.

Les données transférées par l’utilisateur, comme les SMS, le journal d’appels, les contacts, le calendrier, les photos, vidéos, documents ou fichiers audio, ne sont pas transmises à AdMob par notre code.

Les publicités ne doivent pas être affichées pendant les étapes sensibles suivantes :

  • scan ou génération du QR code ;
  • appairage des appareils ;
  • demande de permissions ;
  • transfert de données en cours ;
  • restauration de données sensibles ;
  • changement temporaire d’application SMS ou Téléphone par défaut ;
  • écrans d’explication liés aux permissions sensibles.

6. Consentement publicitaire

Lorsque cela est nécessaire, l’application utilise le système de consentement Google UMP avant d’afficher des publicités personnalisées ou non personnalisées.

L’utilisateur peut être invité à choisir ses préférences de consentement publicitaire selon sa région et les règles applicables.

7. Permissions Android

Les permissions Android sont demandées uniquement lorsque cela est nécessaire pour une fonctionnalité.

  • La caméra peut être utilisée pour scanner un QR code.
  • Les contacts peuvent être lus ou importés si l’utilisateur active le module contacts.
  • Le calendrier peut être lu ou importé si l’utilisateur active le module calendrier.
  • Les fichiers, photos, vidéos et audios sont sélectionnés par l’utilisateur lorsque le module correspondant est utilisé.
  • Les SMS et le journal d’appels peuvent nécessiter des permissions sensibles uniquement si ces modules sont disponibles et activés.

8. SMS

Si le module SMS est disponible, il sert uniquement à migrer les messages de l’utilisateur entre ses appareils.

Android peut imposer que l’application devienne temporairement l’application SMS par défaut pour certaines opérations de restauration. Dans ce cas, l’utilisateur est informé avant la demande et guidé pour remettre son application SMS habituelle après le transfert.

9. Journal d’appels

Si le module d’historique d’appels est disponible, il sert uniquement à migrer ou afficher l’historique d’appels de l’utilisateur.

Selon les restrictions Android et la version de l’application, l’historique d’appels peut être conservé localement dans l’application au lieu d’être restauré directement dans l’application Téléphone native.

10. Conservation locale

L’application n’a pas pour objectif de conserver durablement les données transférées après la fin d’un transfert.

Certaines données peuvent être temporairement traitées en mémoire ou localement pendant la session afin d’assurer le transfert, l’intégrité ou le rapport final.

Si une fonctionnalité affiche localement des données transférées, par exemple un historique d’appels dans l’application, ces données restent sur l’appareil de l’utilisateur et ne sont pas envoyées à nos serveurs.

11. Suppression des données

Les données transférées sont stockées sur les appareils de l’utilisateur. Pour supprimer ces données, l’utilisateur peut les supprimer depuis les applications Android concernées ou depuis les paramètres de son appareil.

Si des données sont stockées localement dans Transfert Données Téléphone, l’utilisateur peut supprimer les données de l’application depuis les paramètres Android de son téléphone.
