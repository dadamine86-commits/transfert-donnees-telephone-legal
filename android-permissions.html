Cette page explique pourquoi l’application Transfert Données Téléphone peut demander certaines permissions Android. Les permissions sont demandées uniquement lorsque l’utilisateur utilise une fonctionnalité qui en a besoin.

1. Principe général

L’application ne demande pas toutes les permissions au démarrage. Les permissions doivent être demandées au moment où l’utilisateur choisit une catégorie de données à transférer.

Si l’utilisateur refuse une permission, le module concerné peut être ignoré ou limité, mais le reste de l’application peut continuer à fonctionner.

2. Caméra

La permission caméra peut être demandée pour scanner un QR code d’appairage entre l’ancien téléphone et le nouvel appareil.

  • Utilisation : scan QR code uniquement ;
  • Moment de la demande : à l’ouverture de l’écran de scan QR ;
  • Publicité : aucune publicité ne doit être affichée pendant le scan QR.

3. Réseau et Internet

Les permissions réseau peuvent être utilisées pour établir une communication locale entre les deux appareils et pour permettre l’affichage de publicités Google AdMob sur les écrans non sensibles.

  • Communication locale entre appareils ;
  • Appairage et transfert local ;
  • Chargement éventuel de publicités sur les écrans autorisés ;
  • Aucun transfert de données personnelles vers un serveur de Neova Labs / SASU AMINE TELECOM.

4. Contacts

Les permissions contacts peuvent être demandées si l’utilisateur choisit de transférer ses contacts.

  • Lecture des contacts sur l’ancien appareil ;
  • Importation des contacts sur le nouvel appareil ;
  • Utilisation uniquement pour le transfert demandé ;
  • Aucune utilisation des contacts pour la publicité.

5. Calendrier

Les permissions calendrier peuvent être demandées si l’utilisateur choisit de transférer ses événements de calendrier compatibles.

  • Lecture des événements compatibles sur l’ancien appareil ;
  • Importation sur le nouvel appareil si Android l’autorise ;
  • Aucune transmission vers un serveur externe ;
  • Aucune utilisation des événements pour la publicité.

6. Photos, vidéos, fichiers et audio

L’application privilégie une sélection manuelle par l’utilisateur pour les photos, vidéos, documents, fichiers et audios.

L’objectif est d’éviter les permissions larges de stockage lorsque les fichiers peuvent être choisis directement par l’utilisateur via un sélecteur Android.

  • L’utilisateur choisit les fichiers à transférer ;
  • L’application ne réalise pas de scan complet du stockage sans action claire ;
  • Les fichiers sélectionnés sont transférés localement ;
  • Les fichiers sélectionnés ne sont pas utilisés pour la publicité.

7. SMS

Si le module SMS est disponible et activé, l’application peut demander l’accès aux SMS uniquement pour permettre leur migration entre deux appareils appartenant à l’utilisateur.

  • Sur l’ancien appareil : lecture des SMS afin de préparer le transfert ;
  • Sur le nouvel appareil : Android peut exiger que l’application devienne temporairement l’application SMS par défaut pour restaurer les SMS ;
  • L’utilisateur doit être informé avant toute demande liée aux SMS ;
  • Après restauration, l’utilisateur est guidé pour remettre son application SMS habituelle ;
  • Le contenu des SMS n’est pas utilisé pour la publicité ;
  • Le contenu des SMS n’est pas envoyé vers un serveur de Neova Labs / SASU AMINE TELECOM.

Le transfert des MMS peut être limité ou non pris en charge selon la version de l’application, Android, l’opérateur ou le téléphone utilisé. Si les MMS ne sont pas pris en charge, cela doit être indiqué clairement à l’utilisateur.

8. Journal d’appels

Si le module d’historique d’appels est disponible et activé, l’application peut demander l’accès au journal d’appels uniquement pour permettre sa migration ou son affichage local dans l’application.

  • Lecture de l’historique d’appels si l’utilisateur accepte la permission ;
  • Transfert local vers le nouvel appareil ;
  • Affichage possible dans une section locale de l’application ;
  • Restauration native dans l’application Téléphone uniquement si Android et les règles applicables l’autorisent ;
  • Aucun appel passé automatiquement ;
  • Aucune utilisation de l’historique d’appels pour la publicité.

9. Notifications

L’application peut demander l’autorisation d’envoyer des notifications si une fonctionnalité en a besoin, par exemple pour informer l’utilisateur pendant un transfert long ou pendant une opération sensible.

Si l’utilisateur refuse les notifications, certaines informations peuvent ne pas être affichées en arrière-plan, mais l’application peut continuer à fonctionner dans les limites imposées par Android.

10. Identifiant publicitaire

Si l’application affiche des publicités via Google AdMob, Android et Google peuvent utiliser l’identifiant publicitaire de l’appareil selon les règles applicables et le consentement de l’utilisateur.

L’identifiant publicitaire n’est pas utilisé par Neova Labs / SASU AMINE TELECOM pour accéder aux données transférées par l’utilisateur.

11. Permissions non utilisées ou évitées

L’application cherche à éviter les permissions trop larges ou non nécessaires.

Selon la version de l’application, les permissions suivantes ne doivent pas être utilisées sans justification forte :

  • accès complet au stockage de l’appareil ;
  • liste complète des applications installées ;
  • installation d’applications externes ;
  • permissions SMS ou appels non nécessaires au transfert ;
  • permissions utilisées hors du contexte clairement expliqué à l’utilisateur.
