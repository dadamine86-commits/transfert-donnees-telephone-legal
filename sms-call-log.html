Cette page explique le fonctionnement prévu des modules SMS et journal d’appels dans l’application Transfert Données Téléphone. Ces modules sont sensibles et sont utilisés uniquement pour permettre la migration des données de l’utilisateur entre ses propres appareils Android.

1. Objectif du module SMS

Le module SMS, lorsqu’il est disponible, sert uniquement à transférer les SMS existants de l’ancien appareil Android vers le nouvel appareil Android de l’utilisateur.

  • Les SMS sont lus uniquement après action explicite de l’utilisateur.
  • Les SMS sont transférés localement entre les deux appareils.
  • Les SMS ne sont pas envoyés vers un serveur de Neova Labs / SASU AMINE TELECOM.
  • Les SMS ne sont pas utilisés pour la publicité.

2. Lecture des SMS sur l’ancien appareil

Sur l’ancien appareil, l’application peut demander l’autorisation de lire les SMS afin de préparer leur transfert. Cette permission est demandée uniquement si l’utilisateur choisit le module SMS.

Si l’utilisateur refuse l’autorisation, le module SMS peut être ignoré et les autres modules de transfert peuvent continuer à fonctionner.

3. Restauration des SMS sur le nouvel appareil

Sur le nouvel appareil, Android peut exiger que l’application devienne temporairement l’application SMS par défaut afin de restaurer les SMS dans l’application Messages du téléphone.

Dans ce cas, l’application doit expliquer clairement la raison de cette demande avant d’ouvrir l’écran système Android correspondant.

  • L’utilisateur reste libre d’accepter ou de refuser.
  • Le rôle SMS par défaut est demandé uniquement pour la restauration des SMS.
  • Après la restauration, l’application guide l’utilisateur pour remettre son application SMS habituelle.
  • L’application ne doit pas envoyer de SMS automatiquement.

4. MMS

Les MMS peuvent contenir des images, pièces jointes et informations dépendantes de l’opérateur ou de l’appareil. Leur transfert peut être limité ou non disponible selon la version de l’application.

Si les MMS ne sont pas pris en charge dans une version de l’application, cela doit être indiqué clairement à l’utilisateur. L’application ne doit pas promettre un transfert MMS complet si cette fonctionnalité n’est pas réellement disponible.

5. Objectif du module journal d’appels

Le module journal d’appels, lorsqu’il est disponible, sert uniquement à transférer l’historique d’appels de l’utilisateur entre ses appareils.

  • Lecture de l’historique d’appels sur l’ancien appareil si l’utilisateur l’autorise ;
  • Transfert local vers le nouvel appareil ;
  • Affichage possible dans une section locale de l’application ;
  • Aucune utilisation de l’historique d’appels pour la publicité ;
  • Aucun envoi de l’historique d’appels vers un serveur externe.

6. Restauration native du journal d’appels

Restaurer le journal d’appels directement dans l’application Téléphone native peut nécessiter des permissions et rôles Android très sensibles.

Si Android exige que l’application devienne temporairement l’application Téléphone par défaut, l’utilisateur doit être informé clairement avant toute demande.

Si cette restauration native n’est pas disponible ou n’est pas activée, l’application peut proposer une alternative : afficher l’historique d’appels transféré dans une section locale de l’application.

7. Appels non passés automatiquement

L’application ne doit pas passer d’appel automatiquement. Elle ne doit pas intercepter volontairement les communications de l’utilisateur.

Le module d’historique d’appels a pour objectif la migration ou l’affichage de données historiques, pas la gestion quotidienne des appels.

8. Publicités interdites sur ces écrans

Les écrans liés aux SMS et au journal d’appels sont considérés comme sensibles. Aucune publicité ne doit être affichée pendant :

  • les explications SMS ;
  • les explications journal d’appels ;
  • les demandes de permissions SMS ou appels ;
  • le changement temporaire d’application SMS par défaut ;
  • le changement temporaire d’application Téléphone par défaut si ce module existe ;
  • la lecture, le transfert ou la restauration des SMS ;
  • la lecture, le transfert ou l’affichage de l’historique d’appels.

9. Consentement utilisateur

Avant toute opération liée aux SMS ou au journal d’appels, l’application doit expliquer :

  • quelle donnée est concernée ;
  • pourquoi la permission est demandée ;
  • comment les données sont transférées ;
  • que les données ne sont pas envoyées à un serveur externe ;
  • que les données ne sont pas utilisées pour la publicité ;
  • que l’utilisateur peut refuser et continuer sans ce module.
